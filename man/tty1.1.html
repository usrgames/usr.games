TTY1(1) General Commands Manual TTY1(1)

NAME

tty1 - the usr.games launcher

SYNOPSIS

tty1 ls
tty1 install name
tty1 update [name]
tty1 run name [argument ...]
tty1 doctor
tty1 man [name]
tty1 help
tty1 --version

DESCRIPTION

tty1 brings the games of usr.games home, keeps them current, and starts them. It keeps what it installs in one folder of its own and puts nothing on your PATH.

tty1 ls
Lists the games: how many play each, which are installed, and which have a newer release. With no network it lists what is installed and says that it could not ask.
tty1 install name
Brings the newest release of a game home. The release is checked first; see HOW A RELEASE IS CHECKED.
tty1 update [name]
Brings an installed game up to date. With no name it does so for every installed game, and then for tty1 itself, if a release built it. A tty1 built with go install is updated the same way it was installed, and says so.
tty1 run name [argument ...]
Starts an installed game and hands it the rest of the line. The game takes the place of tty1, so it has the terminal to itself. This needs no network.
tty1 doctor
Looks at the terminal it is running in and says what it found: whether the terminal tells a game when a key is let go, whether it shows 24-bit colour, and how big it is, with what to change where something can be. A key pressed while it asks, a quarter second at most, is lost.
tty1 man [name]
Shows the manual page of an installed game, with the man(1) of this machine. With no name, or the name tty1, it shows this page.
tty1 help
Shows the commands.
tty1 --version
Says which tty1 this is.

HOW A RELEASE IS CHECKED

A release carries a manifest, which names every file with its size and SHA-256, and a signature of the manifest. tty1 takes the steps below in this order, and stops at the first that fails. Nothing is unpacked before every check has passed, and a game that was installed before stays as it was.

1.
The signature has to be the studio's, made for this program. The one key tty1 trusts is built into it.
2.
The release must not be older than the one installed.
3.
The archive for this machine is downloaded to its end and has to have the size and the SHA-256 the manifest gives.
4.
The archive is unpacked strictly: plain files with plain names, and nothing else.
5.
The game is unpacked beside where it will live and moved into place whole.

The list of games is not trusted. It says what to offer. Whatever name it is given, tty1 installs only what the studio signed under that exact name.

FILES

~/.local/share/tty1/
Everything tty1 writes is in this folder, or in the folder tty1 under XDG_DATA_HOME where that is set. Removing it removes every game tty1 installed.
~/.local/share/tty1/games/name/
An installed game: what its archive held, and the manifest that vouched for it.
~/.local/share/tty1/staging/
A release while it is downloaded and checked. It is empty when tty1 is not at work.
~/.local/share/tty1/man/tty1.1
This page, written here when tty1 man is asked for it.

When tty1 update replaces tty1 itself, it writes the new program beside the old one and moves it over in one step.

ENVIRONMENT

TTY1_HOME
The folder to keep everything in, instead of the one above.
TTY1_SITE
Where the list of games is asked for, instead of https://usr.games.
TTY1_RELEASES
Where the release repositories are asked for, instead of https://github.com/usrgames. A game's releases are in its repository named NAME.6 there, and tty1's own in tty1.
XDG_DATA_HOME
Where programs keep their data, if not in ~/.local/share.
COLORTERM, TERM
What tty1 doctor goes by for colour, as the games do.

The first three are for trying tty1 out. None of them changes whose signature it accepts.

EXIT STATUS

0
What was asked was done.
1
It could not be done. The reason is on the standard error.
2
The command line was not understood.

tty1 run ends with the status of the game it started. tty1 doctor fails only where a game could not run at all: where its input or its output is not a terminal.
